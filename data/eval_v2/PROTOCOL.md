# Протокол оценки обнаружения ПДн (v2)

Документ фиксирует условия эксперимента **до** первого прогона моделей на наборе
`test_v2.jsonl`. Цель — исключить подгонку решения под тест: метрики, сравниваемые
системы и правила принятия решения определены заранее.

**Дата фиксации:** 16.09.2026
**Набор:** `data/eval_v2/test_v2.jsonl`, sha256 указан в `build_report.json`
**Генератор набора:** `data/eval_v2/build_test_v2.py`, seed 20260915

---

## 1. Проблема, ради которой набор пересобран

Прежний held-out (`data/training/test`) порождён тем же генератором, что и обучающая
выборка: **128 из 132** примеров с ПДн (97 %) построены по шаблонам фраз, встречавшимся
в обучении; всего генератор знает 30 шаблонов. Отличались только подставленные значения.
Такой набор измеряет запоминание конструкций, а не способность находить ПДн в незнакомом
тексте, и завышает результат дообученной модели относительно базовой, которая этих
шаблонов не видела.

## 2. Устройство набора v2

Разделение с обучением проведено по трём независимым осям (проверки в
`build_test_v2.py`, результат — `build_report.json`, при нарушении набор не пишется):

| Ось | Правило | Проверка |
|---|---|---|
| Шаблоны фраз | написаны заново вручную | нет совпадений рамок с обучающими; макс. коэффициент Жаккара к ближайшей обучающей рамке приведён в отчёте |
| Лексика ФИО | имена, отчества, фамилии не пересекаются с обучающими словарями | пересечение словарей пусто; ни одно слово из размеченных ФИО теста не встречается в размеченных ФИО обучения |
| Лексика негативов | города, улицы, организации, существительные не из обучающих списков | пересечение словарей пусто |

Дополнительно включены морфологические типы фамилий, отсутствующие в обучении
(-ский/-цкий, -енко, -ых/-их, несклоняемые женские -ук/-ян), и форматы записи ФИО,
которых в обучении не было («Фамилия И.О.», только имя, только фамилия).

Склонение фамилий, имён и отчеств выполнено по явным правилам грамматики и сверено
с pymorphy3: расхождений нет. Автоматическое склонение не использовалось, поскольку
анализатор ошибается на несклоняемых фамилиях («Черных» → «чёрных»), и эти ошибки
несправедливо наказывали бы модели.

Эталонная разметка точна по построению: спан равен позиции вставленного значения.

## 3. Сравниваемые системы

Модели распознавания ФИО прогоняются через **одинаковую** обвязку — ту же, что
в проде (`transformers.pipeline`, `aggregation_strategy="simple"`), без
постобработки сервиса:

| Код | Система |
|---|---|
| S1 | spaCy `ru_core_news_lg` (NER-бэкенд Presidio по умолчанию), метка PER |
| S2 | Natasha (slovnet NER), метка PER |
| S3 | Публичная rubert-tiny2, дообученная на новостях (базовая линия), метки B-PER/I-PER |
| S4 | Наша rubert-tiny2, дообученная под домен обращений, метки B-PERSON/I-PERSON |
| S5 | Сервис целиком (`anonymize_text`) — гибрид модели, spaCy и regex-правил |

S3 и S4 имеют одинаковую архитектуру и размер, поэтому разница S4 − S3 изолирует
вклад дообучения, а не объём модели.

## 4. Метрики

Первичные (по сущностям типа PERSON):

1. **Строгое совпадение** — границы спана совпадают точно (после отбрасывания
   пробелов по краям). Precision, Recall, F1.
2. **Полностью замаскировано** — доля эталонных ФИО, все словоформы которых накрыты
   предсказанием. Метрика приватности: частично накрытое ФИО означает, что часть
   имени осталась в тексте.

Вторичные:

3. Совпадение с пересечением (любое перекрытие, сопоставление один-к-одному).
4. Разбивка по падежу, формату записи, регистру, морфологическому классу фамилии.
5. Ложные срабатывания на негативах: доля текстов без ПДн, где система что-то нашла.
6. Полный конвейер (S5): доля значений ПДн каждого типа, оставшихся в выходном тексте.
7. Латентность (медиана, p95).

F2 не выносится в первичные: он взвешивает полноту выше точности, и на нём выигрыш
выглядит крупнее, чем на F1. Приводится справочно.

## 5. Статистика

- Доверительные интервалы 95 % — **кластерный бутстрап по шаблонам** (10 000 итераций).
  Кластер — шаблон, а не пример: экземпляры одного шаблона зависимы, и обычный
  бутстрап по примерам занизил бы интервалы.
- Сравнение систем — парный бутстрап на тех же выборках; двусторонний p-value.
- Различие считается установленным, если 95 % ДИ разности не содержит нуля.

## 6. Проверяемые гипотезы

- **H1.** S4 превосходит S3 по строгому F1 и по доле полностью замаскированных ФИО
  на наборе v2 (незнакомые шаблоны и незнакомая лексика).
- **H2.** Прирост S4 − S3 на наборе v2 **меньше**, чем на старом наборе; разница
  между наборами количественно оценивает завышение от совпадения шаблонов.

Отрицательный результат по H1 публикуется наравне с положительным.

## 7. Что в оценку не входит и почему

- **43 теста «грязных» форматов** (`tests/test_dirty_formats_regression.py`) — правила
  сервиса дорабатывались именно под эти случаи, для правил это обучающие данные.
- **Реальные обращения пользователей** — содержат настоящие ПДн, в набор не попадают.
- Набор синтетический: он проверяет морфологию, форматы записи и структуру фраз,
  но не воспроизводит опечатки, обрывы и ошибки распознавания речи из реальных
  каналов. Это ограничение указывается в выводах.

## 8. Воспроизводимость

Фиксируются: версии Python и библиотек, sha256 набора и весов моделей, хеш коммита,
сиды. Результаты сохраняются в `data/eval_v2/results/` в формате JSON вместе с
условиями прогона.
