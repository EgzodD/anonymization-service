# Замеры качества по версиям

Качество модуля зависит от трёх вещей: **кода**, **модели ФИО** и **набора данных**.
Если хранить только цифры, через месяц уже не отличить «стало лучше, потому что
поправили правила» от «стало лучше, потому что поменялся набор». Поэтому каждый
снимок хранит цифры вместе с их происхождением.

## Что лежит в снимке

```
benchmarks/v1.0.0/
├── metrics.json   сводка: по каждому набору наши метрики и метрики систем сравнения
├── meta.json      происхождение: коммит, модель ФИО, хеши наборов, версии библиотек
└── raw/           подробные результаты прогона как есть (парный бутстрап, по типам ПДн)
```

Сравнение двух версий = сравнение двух `metrics.json`.

## Как собрать снимок

Снимок **не запускает** прогон — он забирает готовые результаты из
`data/eval_v2/results/`. Сначала прогон (часы на шести наборах), потом снимок:

```bash
python data/eval_v2/run_eval.py          # прогон систем на наборах
python data/eval_v2/compare_competitors.py   # парное сравнение по ФИО
python data/eval_v2/compare_all_types.py     # по всем типам ПДн
python scripts/snapshot_benchmark.py     # версия берётся из app/__init__.py
```

Если id нашей системы в прогоне изменился (`S5-r7` → `S5-r8`), передать
`--our-system S5-r8`. Перезапись существующего снимка — только с `--force`.

## Как читать метрики

| Поле | Что значит |
|---|---|
| `full_masked` | доля сущностей, скрытых **полностью**. Главная метрика для обезличивания: частично закрытое ПДн — утечка |
| `precision` / `recall` / `f1` | строгое совпадение границ спана |
| `f1_overlap` | совпадение с перекрытием (границы не обязаны совпадать точно) |
| `false_person_rate` | доля текстов, где закрыто лишнее — слово, не являющееся ФИО |
| `ours_ci95` | 95 % доверительный интервал по бутстрапу |
| `ours_latency_ms_median` | медианная задержка на текст, мс |

## О полях `commit` и `dirty` в meta.json

`commit` — состояние кода, на котором **шёл прогон**, а не коммит, в котором снимок
попал в репозиторий (цифры получены раньше, чем их успели зафиксировать).
`dirty` — были ли на момент снимка незакоммиченные правки в рабочем дереве.

## Старые замеры

`legacy/` — для графиков и цифр, которые не удаётся привязать к конкретному коммиту.
Прогоны до введения версионирования (июнь – сентябрь 2026) лежат там, где и были
сделаны, — в `data/eval_v2/results/` и `data/training/`; задним числом они в снимки
не раскладываются, потому что неизвестно, какой именно моделью получены.
