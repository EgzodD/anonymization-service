# Журнал изменений

Все заметные изменения модуля обезличивания. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
нумерация — [SemVer](https://semver.org/lang/ru/).

Что означают разряды версии именно в этом проекте:

| Разряд | Повышается, когда | Примеры из нашей истории |
|---|---|---|
| MAJOR | ломается совместимость с клиентом: меняется формат ответа API, имена эндпоинтов, названия плейсхолдеров (`<PHONE>` → `<PHONE_NUMBER>`), состав обязательных переменных окружения | пока не было |
| MINOR | добавлена возможность, старые вызовы работают как раньше | новый тип ПДн, адаптер документов, эндпоинт `/deanonymize`, новая модель ФИО |
| PATCH | исправление без новых возможностей | поправленный regex СНИЛС, закрытая утечка, фикс рассинхрона mapping |

Отдельный раздел **Метрики** приводится там, где прогон измерялся и его результат
лежит в репозитории (`benchmarks/`, `data/eval_v2/results/`). Где замера не было —
раздела нет; задним числом цифры не восстанавливаются.

Теги до `v1.0.0` расставлены задним числом по истории git: это границы этапов,
а не публиковавшиеся наружу релизы.

## [1.0.0] — 2026-10-22

Первый стабильный релиз. Функционально совпадает с состоянием на 18.09.2026
(последняя правка распознавания), после чего шли только измерения, отчёты и
инструменты разработки. Версия объявлена стабильной, потому что формат ответа API,
набор плейсхолдеров и переменные окружения признаны зафиксированными: дальше их
изменение = MAJOR.

### Added
- Версионирование: `CHANGELOG.md`, теги SemVer на всю историю, версия в
  `app/__init__.py` как единственный источник, поле `version` и `person_model` в `/health`.
- `benchmarks/` — замеры, разложенные по версиям: `metrics.json` + `meta.json`
  (коммит, версия модели, хеши наборов, версии библиотек). Снимок собирается
  скриптом `scripts/snapshot_benchmark.py`.
- Сборка Docker-образа тегируется версией: `ANONYMIZER_VERSION=1.0.0 docker compose build`
  даёт `anonymizer:1.0.0` (по умолчанию `anonymizer:dev`).
- Отчёт о тестировании на шести общедоступных наборах с парным бутстрапом и
  сравнением с двумя открытыми системами — по ФИО и по всем типам ПДн
  (поправка 6 протокола, `data/eval_v2/compare_all_types.py`).
- `synthesizer/` — конвейер синтеза обучающих данных: языковая модель пишет текст
  с метками, значения и разметку подставляет наш код. **Инструмент разработки,
  в поставку не входит**, в рантайме сервиса языковые модели не используются.

### Metrics
Текущая версия — `S5-r7`, замер 22.09.2026, подробности в
`benchmarks/v1.0.0/metrics.json`. По ФИО, метрика «значение скрыто полностью»
и строгий F1:

| Набор | Текстов | Скрыто полностью | F1 (строгий) | Ложные ФИО |
|---|---|---|---|---|
| hivetrace/pii-bench | 1810 | 100 % | 0,870 | 2,1 % |
| alrosait (dev) | 4500 | 98,8 % | 0,925 | 8,6 % |
| наш test_v2 | 480 | 96,7 % | 0,951 | 1,3 % |
| factRuEval-2016 | 995 | 90,9 % | 0,846 | 9,0 % |
| redmadrobot/pii_benchmark | 2841 | 81,6 % | 0,638 | 2,9 % |
| MultiCoNER ru | 4000 | 78,4 % | 0,302 | 21,5 % |

Медианная задержка 10–18 мс на текст против 36–56 мс у `rubert-base-pii-ner`.
Слабое место зафиксировано честно: MultiCoNER — новости с одиночными фамилиями и
иноязычными именами строчными буквами.

## [0.10.0] — 2026-09-18

Этапы 0–3 плана улучшений: правила для структурированных ПДн, фильтр ложных ФИО,
модель ФИО v3, переписанные адреса.

### Added
- dev-наборы (`dev_v2`, `dev_rmr`) и гейт-храповик: правила настраиваются только на
  dev, приёмочные наборы тратятся один раз.
- Правила для структурированных ПДн (этап 1) и фильтр ложных срабатываний PERSON
  на основе pymorphy3 (этап 2).
- Внешние наборы: factRuEval-2016 (поправка 2), hivetrace/pii-bench, alrosait,
  MultiCoNER ru (поправка 4).
- Поправки 3–5 протокола оценки, записанные **до** прогонов.

### Changed
- Модель ФИО v3 в работе: все пять предрегистрированных критериев приёмки
  выполнены, порог гейта качества ужесточён.
- Распознаватель адресов переписан по разбору утечек; обратный порядок слов,
  падежи и строчное написание.

### Metrics
- hivetrace: доля текстов с открытым ПДн 8,0 % → 2,4 %.
- alrosait: 17,2 % → 1,1 %; адреса, открытые целиком, 36 % → 2 %.
- Строгий F1 по ФИО на hivetrace: 0,636 → 0,845.

## [0.8.0] — 2026-08-25

Обратимость, адреса и закрытие утечек по итогам состязательного QA.

### Added
- Эндпоинт `/deanonymize`: восстановление текста по `mapping`
  (сценарий «безопасная языковая модель в контуре»).
- Распознаватель `ADDRESS` (город / улица / дом / квартира).
- Доступ к `mapping` — secure-by-default, выдача пишется в аудит.
- Покрытие «грязных» реальных форматов ПДн, веб-стенд в отдельной папке.

### Fixed
- Рассинхрон обезличенного текста и `mapping`: текст строился из сырого вывода
  presidio, а `mapping` — из резолвнутого набора, из-за чего на неоднозначных
  числах плейсхолдер в тексте (`<PASSPORT>`) расходился с ключом `mapping`
  (`<PHONE>`) и спан невозможно было деобезличить.
- Четыре утечки и одно перемаскирование из состязательного QA (раунд 2).
- Таблицы `.docx`: учтён контекст строки (закрыта утечка «ключ в соседней ячейке»).
- Перемаскирование голых чисел: снят встроенный телефон presidio и
  context-free паспорт.
- Ложные ФИО: обрезанный префикс слова (`банков<PERSON>ская`), слово-метка
  («Паспорт»).

### Removed
- Веб-демо страница `/demo` (заменена отдельным веб-стендом вне прод-кода).

## [0.7.0] — 2026-08-04

Обезличивание документов.

### Added
- Адаптер документов за флагом `DOCUMENT_ENABLED`, эндпоинт `/anonymize/document`:
  `.docx` через python-docx (тело, таблицы, колонтитулы, очистка метаданных) и PDF
  растеризацией pdfplumber + pypdfium2 + Pillow. Все зависимости MIT/BSD/Apache —
  PyMuPDF отвергнут из-за AGPL; текстового слоя на выходе PDF нет намеренно.
- 18 тестов адаптера.

### Changed
- Дообучение ФИО на топонимах: город больше не поглощается в ФИО, сняты два xfail
  («Санкт-Петербург», «Иван Петров из Москвы»).

### Metrics
- Ложные срабатывания на сторожевом наборе: 7 → 5 (остаток — 3 regex, 2 модельных).
- LeakRate 0 %, recall по ФИО 100 % сохранены.

## [0.6.0] — 2026-08-03

Дата рождения, негативные примеры, оценка по типам ПДн.

### Added
- `eval_per_type.py` и дашборд качества по типам ПДн.
- Негативные примеры в тест-наборе и precision-сторож.
- Аугментация обучения негативами: топонимы и частые слова как `O`, ФИО рядом с
  городом — в отдельные `train/dev_negatives`.
- Пункт «Демо» в меню тестов: печать вход → выход (без `mapping`).

### Changed
- Данные переехали в `data/training` — гейт приватности снова выполняется, а не
  молча пропускается из-за битых путей.
- `entities_found` строится по резолвнутому набору: пропали дубли-пересечения на
  одном значении, выдача согласована с текстом и `mapping`.
- Обновлены уязвимые зависимости (fastapi 0.115 → 0.141, starlette 0.41 → 1.3.1,
  python-dotenv, pytest), скан pip-audit в проверках снова блокирующий.

### Metrics
- `DATE_OF_BIRTH`: 28 из 28 дат рождения под верным плейсхолдером (было 9 из 28,
  остальные уходили под общий `<PII>`).
