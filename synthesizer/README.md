# Синтезатор обучающих данных

Генерация обращений клиентов с персональными данными и **точной разметкой** — для
дообучения модели ФИО. Отдельный проект внутри модуля: в продакшен-сервис не входит,
запускается руками, результат — файл с обучающими примерами.

Статус: **версия 2 готова, генерация объёма не запущена** (ждёт подтверждения юриста,
см. «Ограничения»). Задача 3а в `БУДУЩИЕ_ПЛАНЫ.md`.

## Зачем

Главное ограничение качества модели ФИО — данные, а не железо. Размеченных русских
обращений в открытом доступе почти нет, ручная разметка стоит дорого и даёт ошибки
(расхождение разметчиков), а разметка, которую рисует языковая модель, систематически
кривая: она путает границы имени и пропускает инициалы.

## Как это работает

Ключевая идея: **языковая модель не пишет персональные данные вообще.**

1. Модель пишет только текст обращения с метками: `[ТЕЛЕФОН]`, `[ПАСПОРТ]`, `[АДРЕС]`…
   Людей она называет условными именами («Иван Иванович Петров») и склоняет их сама —
   склоняет хорошо, а вот метки с падежом (`[ФИО:дат:ж]`) ставила неверно.
2. Значения подставляет наш код: имена из лексикона в нужном падеже и роде, номера с
   верными контрольными суммами, «грязные» форматы. Позиции известны по построению —
   **разметку невозможно получить сдвинутой.**
3. После подстановки код портит текст опечатками и иногда переводит его в нижний регистр —
   только вне подставленных значений, с пересчётом позиций.
4. Каждый текст проходит автопроверки; брак отбрасывается.

Всё локально через Ollama (по умолчанию `qwen3:8b`, Apache-2.0): бесплатно, ни один
текст не покидает машину.

## Запуск

```bash
ollama serve                                    # если ещё не запущен
.venv/bin/python -m synthesizer.generate --n 50  # прогон; результат в synthesizer/runs/
.venv/bin/python -m synthesizer.review synthesizer/runs/<файл>.jsonl > <файл>_review.txt
```

Полезные ключи: `--n` сколько текстов, `--per-request` текстов за запрос (больше трёх —
модель теряет список требований), `--neg-share` доля текстов только из трудных негативов,
`--typo-share` доля текстов с опечатками, `--dup-threshold` порог почти-дубля,
`--model` другая модель в Ollama, `--seed` воспроизводимость.

Скорость на нашем CPU — 29–35 с на текст, то есть 10 000 обращений ≈ 80–95 часов фоном.

## Что где лежит

| файл | ответственность |
|---|---|
| `values.py` | подстановка значений и разметка; условные люди, лексиконы, трудные негативы |
| `scenarios.py` | матрица сценариев (сфера × канал × стиль × длина × ПДн × негативы) и запрос к модели |
| `llm.py` | обращение к Ollama по JSON-схеме |
| `corrupt.py` | опечатки и нижний регистр, пометки испорченных слов |
| `dedup.py` | отсев почти-дублей (Жаккар по тройкам слов, обратный индекс) |
| `generate.py` | точка входа: сборка набора, автопроверки, отчёт |
| `review.py` | выгрузка прогона для ручной проверки глазами |
| `runs/` | результаты: `.jsonl` не коммитятся, отчёты и выгрузки — коммитятся |

Инварианты закреплены тестами: `tests/test_synthesizer.py` (входит в общий прогон
`./scripts/check.sh`). Главный из них — порча опечатками и нижний регистр не сдвигают
разметку: если она поедет молча, узнаем об этом только по качеству модели через дни
обучения.

## Автопроверки

Брак (`reject=True`): `unknown_tag` — метка не из списка или метка человека без падежа;
`leftover` — остались скобки; `duplicate` / `near_duplicate` — повтор; `no_tags` — нет
меток там, где сценарий их требовал; `no_person` — сценарий просил человека, а модель его
не упомянула; `extra_pii` — персональные данные вписала сама модель (в обучающих данных
окажется неразмеченное имя или номер).

**Что браком не считается.** Набор синтетический, поэтому всё вне разметки персональными
данными не является по построению. Если сервис находит ФИО на трудном негативе
(тариф «Евгений Онегин») или на слове, которое мы испортили («чтобыы»), — это **его**
ложное срабатывание, а текст годный и как раз самый ценный. Такие случаи идут в отчёт
отдельно (`person_fp_on_negatives`, `person_fp_on_typos`) и дают бесплатную оценку
лишних масок на каждом прогоне.

| прогон | текстов | брак | макс. сходство | с/текст | примечание |
|---|---|---|---|---|---|
| 2026-09-21, пилот 1 | 50 | 0 | не измерялось | 14,5 | версия 1; тексты однообразные, опечаток нет |
| 2026-10-05, пилот 2 | 50 | 0 | 0,049 | 29,3 | версия 2; 11 сфер, 63 негатива, 18 текстов с опечатками |
| 2026-10-05, пилот 3 | 20 | 2 | 0,053 | 35,2 | подтверждение проверки `no_person`; оба брака — по ней |

Найденные ложные срабатывания сервиса (пилоты 2–3): на опечатках — «можо», «чтобыы»,
«мення», «нунжо», «зздравствуйте», «озвони», «расписнаия», «Здравствуйие»; на
названиях-именах — «Евгений Онегин», «Борис Годунов», «Мчедлишвили». Улицы по фамилиям
(«ул. Гагарина») и большинство организаций сервис проходит чисто.

## Ограничения

1. **Синтетика — для обучения, НЕ для приёмки.** Проверка модели на синтетике того же
   происхождения завышает оценку (вывод нашей статьи, раздел 2). Приёмка следующей модели
   ФИО — только на наборе из реальных обращений (пункт 2 в `БУДУЩИЕ_ПЛАНЫ.md`).
2. **Перед генерацией объёма нужно подтверждение юриста**, что тексты, написанные
   языковой моделью, можно использовать в коммерческом продукте. Лицензия весов
   (Apache-2.0) этот вопрос не закрывает.
3. **Лексиконы** проверены на непересечение с отложенными наборами (`generate_v3.check_disjoint`),
   но сам синтезатор этой проверки не повторяет: он берёт уже проверенные лексиконы.
